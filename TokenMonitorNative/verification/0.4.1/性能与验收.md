# 0.4.1（构建 21）性能与交互验收

2026-09-13，macOS 27 beta（26A428），Xcode beta，release 原生 Swift Package 构建。

## 已解决的热点

- 真实应用的主线程采样确认 `OverviewView.sections → quotaProviders → tools → Device.hasUsableData → DateCodec.parse` 反复创建 ISO8601DateFormatter。现在用两个受锁保护的格式器及最多512条缓存（含失败结果），并按快照、来源和过期边界缓存展示清单。
- 周期、来源、主题与布局是独立观察字段；每秒时钟不再使整页失效。普通设置延迟150ms合并保存；编码/磁盘写入在独立 actor 上，修订号阻止旧任务覆盖新数据。连接设置写入成功后才启用；退出等待最终保存。
- 窗口维持最小320×400 pt，根 hosting view 不推导额外尺寸。原生滚动视口拥有宽度，SwiftUI只回报内容高度，避免重复整树测量。
- 宽热力图复用基础历史投影，只补齐左侧空日期；拓宽到190周不会重新解析原有日期。回归测试覆盖此路径。图表宿主只在数据或相关外观改变时更新。

## 测量方法与结果

使用实际 `PanelController` 小窗、原生周期工具栏、底部玻璃操作、时钟和 `AppStore.accept` 接收路径。覆盖320、600、1000、1920 pt，120次往返宽度变化、60次周期切换和6次快照接收。旧版为修改前源码副本，只加入相同验证入口。

真实回放保留110条日记录及设备/工具/额度结构；时间戳整体平移以保持原有相对过期关系。另测1095天合成历史。回放不读取密钥、不联系Hub、不改用户设置。

同步主线程工作包含设置窗口大小/周期、布局和显示请求。16ms节拍另行等待；“额外调度延迟”仅是等待实际返回时间减16ms，捕捉延后执行的工作，**不能解释成屏幕FPS或GPU呈现时间**。

| 周期切换同步工作中位数 | 300.33 ms | 8.65 ms |
| 周期切换同步工作P95 / 最大 | 305.33 / 313.85 ms | 10.43 / 10.64 ms |

同步 resize 单项并非所有值都下降；旧版的主要停顿发生在延后的整页刷新。修复后连续交互的长停顿显著减少。5ms是努力目标，并非所有工作都已达到；不宣称每一帧满足高刷新率显示预算。

三年历史复测：同步resize P95从32.02ms降至10.26ms、最大从41.28ms降至12.39ms；周期最大从18.23ms降至12.07ms。额外调度延迟P95从11.28ms降至8.09ms，最大从12.98ms降至8.13ms。原始记录见本目录文本。

## 验证限制

- Instruments SwiftUI 模板进行了多次采集，包括完整签名应用、10秒预热及启用布局记录。最终轨迹有25,251条 Time Profiler 样本，但 SwiftUI updates 为0，工具报告 “Trace file had no SwiftUI data”。因此**未宣称完成更新因果图验收**；没有将原因推测成确定的系统缺陷。
- 最终 Instruments 记录报告一次572.57ms启动阶段停顿（1.096秒处，发生在10秒预热/交互测试之前）；未报告之后测试阶段超过250ms的停顿。这是启用采集器的启动结果，不代表普通启动耗时。
- 自动鼠标拖窗仍被 Computer Use 工具 `windowNotFoundAtPosition` 阻断。真实手指持续拖动、物理滑块拖拽和全套VoiceOver导航仍需人工体验复核。程序化实际窗口resize、原生滚轮及无障碍滑块操作、布局和数据语义已有验证。
- 主线程采样 `/tmp/token-monitor-041-final-sample.txt` 中，历史完整投影只出现在初次渲染，连续resize路径不再重复解析；对应回归测试确保改变16…190周容量不会增加基础投影次数。
